# 抖音采集与视频发布

本版使用同一个加密账号服务供采集和发布使用。已有扫码账号直接出现在发布页面；只有手工粘贴 Cookie 到采集身份池、没有原始浏览器记录的账号，需要先扫码保存完整登录信息。

## 控制台操作

1. 使用管理员账号登录。打开“发布视频”，选择已有抖音账号，或者点击“扫码登录抖音”。
2. 选择本地 MP4、MOV 或 M4V 视频，填写最多 30 字的标题和最多 1000 字的正文。
3. 点击“上传到本机并检查账号”。这一步把文件保存到当前实例，并只读检查创作者登录，显示平台返回的昵称和账号编号。
4. 核对后点击“确认发布到抖音”。确认框中的账号是最终目标；任务不会因失败换到另一个账号。
5. 查看发布记录。“已提交”表示作品管理列表中确认了新的作品编号，作品最终展示仍由平台审核决定。

默认不填写素材来源或 AI 生成声明，不开启第三方平台同步。需要平台专用声明、定时、封面或其他高级选项的作品，应先在创作者中心处理；当前页面只提供基础视频发布。

## 会话与任务

- 原始 Cookie、域名、路径、localStorage 等浏览器会话保存在加密 Vault；现有管理员接口只向页面返回账号摘要。
- 检查和发布使用同一账号。会话更新按版本比较写回；等待确认期间如果重新扫码，需要重新检查。
- 控制台在检查或发布结束后自动调用同步接口，将当前登录态加密导入采集身份池。原有重复导入及更新逻辑继续生效；同步失败可单独重试。
- 单个视频最大 1 GiB，本机待处理素材总量上限 10 GiB。传输使用流式处理，不将整个视频装入 API 内存。
- 视频保存在扫码数据卷的 `publishing/` 下。已提交或结果不确定的素材会清理，未提交素材在一天后于下次清理时删除；可随时清理未运行的本机草稿。
- SQLite 保存发布记录与提交状态，不含 Cookie。一个账号服务进程同一时间执行一个浏览器发布或检查；请保留默认单进程启动方式，不要同时启动多个进程共写同一个账号目录。
- 服务在最终点击之前持久化“正在提交”。之后断线、超时或重启时标为结果待核实，不自动重发。请到作品管理核对已有作品，再决定是否创建新任务。
- 本机草稿清理不会删除平台作品。

平台额外要求手机验证时，任务停止并反馈。登录有效期只是预计时间；发布前始终再次检查创作者账号，不把采集成功当作发布授权有效的依据。

## Agent / API

与页面使用同一组接口。需要管理员会话，或管理员持有的 `admin` scope API Key。真实 Cookie 无需交给 Agent。

| 方法 | 路径（前缀 `/api/v1/admin/publishing`） | 用途 |
|---|---|---|
| GET | 空路径 | 保存的账号摘要与最近 100 条任务 |
| POST | `/jobs` | 创建本机草稿，提供 `account_id`、`client_key`、`title`、`description`、`filename`、`size` |
| PUT | `/jobs/{id}/video` | 请求体为视频原始字节，字节数必须与 `size` 一致 |
| POST | `/jobs/{id}/prepare` | 异步检查真实创作者账号 |
| GET | `/jobs/{id}` | 读取任务状态 |
| POST | `/jobs/{id}/sync` | 在 `ready` 或 `published` 后同步采集登录态 |
| POST | `/jobs/{id}/publish` | 明确提交：`{"account_id":"已检查的账号 ID","confirm":true}` |
| DELETE | `/jobs/{id}` | 清理未运行的本机草稿 |

`client_key` 使用随机的 32 位十六进制值。同一次创建请求重试应使用相同值和相同内容，避免生成重复草稿。`prepare` 后轮询至 `ready`，核对昵称和账号编号，再进行用户已经授权的发布。`publish` 的响应丢失时先读取原任务，不创建新任务重发；重复调用同一任务不会再次提交。

## Docker 更新

仍使用 `compose.qr.yaml` 和现有 `.env.qr`。应用镜像为 `dtk-qr-app:5.1.7-unified1`，账号服务为 `dtk-qr-login:0.3.0`，保留 `qr-data` 和全部现有卷。主数据库仍为 `0018`，不增加或替换 PostgreSQL 迁移。

旧 Vault 记录会按需转换为浏览器会话，不需要重新生成密钥。更新前备份数据库、`.env.qr` 和整个 `qr-data`，包括发布记录和待处理素材。若要回退，保留该目录及密钥，使用更新前的镜像和配置。

本次只读实测验证了已有扫码凭证能读取创作者昵称与账号编号；提交流程通过模拟平台的真实后台浏览器测试。不会为安装验证自动发布真实作品。
